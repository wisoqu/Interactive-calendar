# Интерактивный школьный календарь (Interactive School Calendar)

Веб-приложение для совместного планирования школьных мероприятий, контрольных работ, классных часов, олимпиад и собраний внутри учебных групп (классов) с ролевой моделью доступа.

---

## О проекте (материал для выступления и презентации)

### Актуальность и решаемая проблема
В школьной жизни расписание контрольных, консультаций, экскурсий и классных собраний часто теряется в десятках сообщений в мессенджерах и устных объявлениях. Когда информация не собрана в единой структуре, ученикам и классным руководителям сложно быстро проверить актуальные даты и избежать накладок по времени.

**Цель проекта** — создать легкое, автономное и простое в развертывании веб-приложение, которое объединяет события класса в общем интерактивном календаре с разграничением прав доступа.

### Ключевые возможности
1. **Три режима просмотра календаря**
   - **Месяц (сетка)** — наглядный обзор всех учебных недель месяца.
   - **Неделя (почасовая шкала)** — детальное планирование времени по дням недели.
   - **Список (хронология)** — упорядоченная лента предстоящих событий с описаниями и авторами.
2. **Удобное планирование без ошибок**
   - Встроенный 4-шаговый мастер выбора даты и времени начала/окончания.
   - Автоматическое предупреждение о пересечении по времени с другими мероприятиями класса.
   - Хранение времени в формате UTC на сервере с автоматическим переводом в часовой пояс пользователя.
3. **Изолированные учебные группы (классы)**
   - Быстрое вступление учеников по уникальному 6-символьному коду приглашения (с копированием в один клик).
   - Управление вступлением: владелец может временно **закрыть вход по коду** или задать **максимальный лимит участников** (например, 30 человек).
4. **Безопасность и восстановление доступа**
   - Хеширование паролей алгоритмом `PBKDF2-SHA256` (100 000 итераций, уникальная соль).
   - Серверные сессии на базе защищенных `HttpOnly` cookie (без хранения токенов в `localStorage`).
   - Восстановление забытого пароля по 6-значному одноразовому коду через электронную почту (SMTP): на сервере хранится только `SHA-256` хеш кода (срок действия — 15 минут), а при смене пароля все прежние сессии автоматически отзываются.
5. **Адаптивный интерфейс**
   - Поддержка **светлой и темной темы** оформления, переключение русского и английского языка (`RU` / `EN`), адаптация под компьютеры и смартфоны.

## Архитектура и технологический стек

Приложение построено как монолитное клиент-серверное веб-приложение с минимальным потреблением ресурсов — оно стабильно работает даже на самом недорогом VPS (от **512 МБ – 1 ГБ ОЗУ**, 1 vCPU), потребляя в работе около **60–90 МБ оперативной памяти**.

| Уровень | Технологии | Назначение в проекте |
| :--- | :--- | :--- |
| **Клиентская часть (Frontend)** | **React 19**, **TypeScript**, **Vite 6** | Одностраничное приложение (SPA), строгая типизация моделей, мгновенная сборка статики |
| **Стилизация и UI** | **Tailwind CSS 4**, **Lucide React** | Высококонтрастный интерфейс без визуального шума, светлая/темная тема, векторные иконки |
| **Серверная часть (Backend)** | **Node.js 20**, **Express**, **esbuild / tsx** | Обработка REST API, проверка прав ролей (RBAC), управление сессиями и раздача статики |
| **База данных** | **SQLite (`better-sqlite3`)** в режиме **WAL** | Встраиваемая реляционная СУБД в одном файле (`./data/calendar_db.sqlite`) с индексами, без затрат ОЗУ на отдельный сервер БД |
| **Почтовый модуль** | **Nodemailer (SMTP)** | Отправка одноразовых 6-значных кодов восстановления пароля с настраиваемой почты |
| **Инфраструктура** | **Docker**, **Docker Compose**, **Nginx + Certbot** | Контейнеризация в один образ `node:20-alpine`, обратный прокси и автоматический HTTPS (порт 443) |

### Модель данных (SQLite)
В базе данных используются 6 связанных таблиц с индексами:
- `users` — учетные записи пользователей (`id`, `username`, `email`, `password_hash`, `created_at`).
- `classrooms` — учебные группы (`id`, `name`, `description`, `owner_id`, `invite_code`, `is_closed`, `max_members`, `created_at`, `updated_at`).
- `members` — связь пользователей с группами и их роль (`owner`, `admin`, `member`), уникальность пары `(user_id, classroom_id)`.
- `events` — календарные события класса (`title`, `description`, `starts_at`, `ends_at`, `creator_id`).
- `sessions` — серверные сессии авторизации с поддержкой мгновенного отзыва (`revoked_at`).
- `reset_codes` — одноразовые коды сброса пароля (`code_hash`, `expires_at`, `used_at`).

## Ролевая модель доступа (RBAC)

Права пользователя определяются отдельно внутри каждого класса:

| Действие в классе | Владелец (`owner`) | Администратор (`admin`) | Участник (`member`) |
| :--- | :---: | :---: | :---: |
| Просмотр календаря, деталей событий и списка участников | Да | Да | Да |
| Создание, редактирование и удаление событий | Да | Да | Нет |
| Добавление обычных участников по логину | Да | Да | Нет |
| Исключение обычных участников (`member`) | Да | Да | Нет |
| Назначение и снятие администраторов (`admin`) | Да | Нет | Нет |
| Изменение настроек класса, закрытие входа, лимит участников | Да | Нет | Нет |
| Удаление класса | Да | Нет | Нет |
| Самостоятельный выход из класса | Нет (только удаление класса) | Да | Да |

## Быстрая установка на сервер (одной командой)

Для развертывания на чистом сервере **Ubuntu 20.04 / 22.04 / 24.04** или **Debian 11 / 12** выполните в терминале (под `root` или пользователем с `sudo`):

```bash
bash <(curl -Ls https://raw.githubusercontent.com/wisoqu/Interactive-calendar/main/install.sh)
```

### Что делает интерактивный установщик `install.sh`
Каждый шаг в консоли подписан (`[ОБЯЗАТЕЛЬНО]` или `[НЕОБЯЗАТЕЛЬНО — нажмите Enter, чтобы пропустить]`):
1. **Проверяет ОЗУ сервера**: если памяти меньше 2 ГБ и нет подкачки, предлагает автоматически создать `SWAP` на 2 ГБ для стабильной сборки на бюджетном VPS.
2. **Проверяет и ставит зависимости**: при необходимости автоматически устанавливает `git`, `curl`, `Docker` и `Docker Compose`.
3. **Скачивает проект** в `/opt/interactive-calendar` (или в указанную вами директорию) и создает папку `./data` для постоянного хранения базы SQLite.
4. **Настраивает отправку писем (SMTP)**: запрашивает адрес и пароль приложения вашей почты (шаг можно пропустить нажатием `Enter`).
5. **Собирает и запускает Docker-контейнер** и проверяет готовность сервера через `/api/health`.
6. **Настраивает домен и HTTPS на 443 порту** *(по желанию)*: если указать домен, скрипт сам установит `Nginx` + `Certbot`, пропишет проксирование и выпустит бесплатный SSL-сертификат Let's Encrypt с редиректом `HTTP -> HTTPS`. Если домена нет, приложение сразу доступно по `http://<IP-сервера>:3000`.

## Как правильно настроить почту (SMTP) для сброса пароля

Чтобы приложение отправляло реальные письма с 6-значным кодом восстановления пароля, почтовые сервисы требуют использовать специальный **Пароль приложения** (ваш обычный пароль от почты для входа в браузере не подойдет из-за защиты аккаунтов).

### Вариант 1. Google Почта (Gmail)
1. Откройте [Настройки аккаунта Google -> Безопасность](https://myaccount.google.com/security).
2. Включите **Двухэтапную аутентификацию** (2-Step Verification).
3. В поиске по настройкам аккаунта введите **«Пароли приложений»** (*App passwords*) и создайте новый пароль (получится 16 символов).
4. Укажите при установке или в файле `.env`:
   ```env
   SMTP_HOST="smtp.gmail.com"
   SMTP_PORT=587
   SMTP_USER="ваш_адрес@gmail.com"
   SMTP_PASS="16_символьный_пароль_приложения"
   SMTP_FROM="Школьный календарь <ваш_адрес@gmail.com>"
   SMTP_SECURE=false
   ```

### Вариант 2. Яндекс Почта
1. Откройте [Яндекс ID -> Безопасность -> Пароли приложений](https://id.yandex.ru/security/app-passwords) и включите пароли приложений.
2. Создайте пароль для типа **«Почта»**.
3. В разделе настроек Яндекс Почты «Почтовые программы» убедитесь, что разрешен доступ к почтовому ящику с помощью почтовых клиентов.
4. Укажите при установке или в файле `.env`:
   ```env
   SMTP_HOST="smtp.yandex.ru"
   SMTP_PORT=465
   SMTP_USER="ваш_логин@yandex.ru"
   SMTP_PASS="пароль_приложения_яндекса"
   SMTP_FROM="Школьный календарь <ваш_логин@yandex.ru>"
   SMTP_SECURE=true
   ```

### Вариант 3. Почта Mail.ru
1. Перейдите в [Настройки Mail.ru -> Безопасность -> Пароли для внешних приложений](https://account.mail.ru/user/2-step-auth/passwords/) и создайте новый пароль.
2. Укажите при установке или в файле `.env`:
   ```env
   SMTP_HOST="smtp.mail.ru"
   SMTP_PORT=465
   SMTP_USER="ваш_ящик@mail.ru"
   SMTP_PASS="пароль_внешнего_приложения"
   SMTP_FROM="Школьный календарь <ваш_ящик@mail.ru>"
   SMTP_SECURE=true
   ```

> **Как изменить или включить почту уже после установки?**  
> Отредактируйте файл `/opt/interactive-calendar/.env` и пересоздайте контейнер одной командой:
> ```bash
> cd /opt/interactive-calendar
> nano .env
> docker compose up -d
> ```

## Ручная настройка HTTPS (Nginx + порт 443)

Если во время работы `install.sh` вы пропустили ввод домена и хотите подключить HTTPS позже вручную:

1. Направьте `A`-запись вашего домена на IP-адрес сервера и установите пакеты:
   ```bash
   sudo apt-get update
   sudo apt-get install -y nginx certbot python3-certbot-nginx
   ```
2. Создайте файл `/etc/nginx/sites-available/interactive-calendar`:
   ```nginx
   server {
       listen 80;
       listen [::]:80;
       server_name calendar.example.ru; # укажите ваш домен

       location / {
           proxy_pass http://127.0.0.1:3000;
           proxy_http_version 1.1;
           proxy_set_header Upgrade $http_upgrade;
           proxy_set_header Connection 'upgrade';
           proxy_set_header Host $host;
           proxy_set_header X-Real-IP $remote_addr;
           proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
           proxy_set_header X-Forwarded-Proto $scheme;
       }
   }
   ```
3. Активируйте конфигурацию и выпустите сертификат Let's Encrypt (Certbot сам переведет сайт на порт `443` и включит автопродление):
   ```bash
   sudo ln -sf /etc/nginx/sites-available/interactive-calendar /etc/nginx/sites-enabled/interactive-calendar
   sudo nginx -t && sudo systemctl reload nginx
   sudo certbot --nginx -d calendar.example.ru
   ```

## Локальный запуск для разработки и проверки

Требуется установленный **Node.js 20+**.

```bash
# 1. Клонирование репозитория и установка пакетов
git clone https://github.com/wisoqu/Interactive-calendar.git
cd Interactive-calendar
npm install

# 2. Создание файла окружения (по желанию заполните SMTP_*)
cp .env.example .env

# 3. Запуск в режиме разработки (доступно на http://localhost:3000)
npm run dev

# 4. Автоматический прогон проверочных сценариев (регистрация, RBAC, лимиты, сброс пароля, SQLite)
npm test

# 5. Сборка производственной версии
npm run build
npm start
```
