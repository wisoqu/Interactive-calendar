# Интерактивный школьный календарь (Interactive School Calendar)

Веб-приложение для совместного планирования школьных мероприятий, контрольных работ, классных часов, олимпиад и собраний внутри учебных групп (классов) с ролевой моделью доступа.

---

## О проекте (материал для выступления и презентации)

### Актуальность и решаемая проблема
В школьной жизни расписание контрольных, консультаций, экскурсий и классных собраний часто теряется в десятках сообщений в мессенджерах и устных объявлениях. Когда информация не собрана в единой структуре, ученикам и классным руководителям сложно быстро проверить актуальные даты и избежать накладок по времени.

**Цель проекта** — создать легкое, автономное и простое в развертывании веб-приложение, которое объединяет события класса в общем интерактивном календаре с разграничением прав доступа.

### Ключевые возможности
1. **Три режима просмотра календаря**
   - **Месяц (сетка)** — наглядный обзор всех учебных недель месяца с поддержкой многодневных мероприятий.
   - **Неделя (почасовая шкала)** — детальное планирование времени по дням недели (сетка автоматически расширяется при наличии ранних или поздних событий вне диапазона `08:00–22:00`).
   - **Список (хронология)** — упорядоченная лента событий с фильтром «Предстоящие / Все / Прошедшие», описаниями и авторами.
2. **Удобное планирование без ошибок**
   - Встроенный 4-шаговый мастер выбора даты и времени начала/окончания.
   - Автоматическое предупреждение о пересечении по времени с другими мероприятиями класса.
   - Хранение времени в формате UTC на сервере с автоматическим переводом в часовой пояс пользователя и поддержка навигации браузера (`#/home`, `#/classroom/:id/:tab`).
3. **Изолированные учебные группы (классы)**
   - Быстрое вступление учеников по уникальному 6-символьному коду приглашения (с копированием в один клик, включая резервный способ для HTTP без HTTPS).
   - Управление вступлением: владелец может временно **закрыть вход по коду** или задать **максимальный лимит участников** (например, 30 человек).
4. **Безопасность и восстановление доступа**
   - Асинхронное хеширование паролей алгоритмом `PBKDF2-SHA256` (100 000 итераций, уникальная соль, ограничение длины пароля 6–128 символов — без блокировки event loop).
   - Серверные сессии строго через `HttpOnly` + `SameSite=Lax` cookie (токен никогда не передается в JSON и не хранится в `localStorage`/`sessionStorage`), проверка `Origin`/`Referer` для защиты от CSRF, защитные HTTP-заголовки (включая HSTS при HTTPS) и rate limiting на чувствительные маршруты. Лимиты привязаны к аккаунту (логин/email) и к пользователю для вступления по коду, поэтому целый класс за одним школьным NAT не блокирует друг друга; значения настраиваются через `RATE_LIMIT_*` в `.env`.
   - Восстановление забытого пароля по 6-значному одноразовому коду через электронную почту (SMTP): на сервере хранится только `SHA-256` хеш кода (срок действия — 15 минут, блокировка после 5 неудачных попыток, без раскрытия наличия email в базе), а при смене пароля все прежние сессии автоматически отзываются.
5. **Адаптивный интерфейс**
   - Поддержка **светлой и темной темы** оформления, переключение русского и английского языка (`RU` / `EN`), локализация всех ошибок API, адаптация под компьютеры и смартфоны.

## Архитектура и технологический стек

Приложение построено как модульное клиент-серверное веб-приложение с минимальным потреблением ресурсов — оно стабильно работает даже на недорогом VPS (от **512 МБ – 1 ГБ ОЗУ**, 1 vCPU), потребляя в работе около **60–90 МБ оперативной памяти**.

| Уровень | Технологии | Назначение в проекте |
| :--- | :--- | :--- |
| **Клиентская часть (Frontend)** | **React 19**, **TypeScript (`strict: true`)**, **Vite 6** | Одностраничное приложение (SPA), строгая типизация, модульные представления календаря |
| **Стилизация и UI** | **Tailwind CSS 4**, **Lucide React** | Высококонтрастный интерфейс без визуального шума, светлая/темная тема, векторные иконки |
| **Серверная часть (Backend)** | **Node.js 22+** (Docker-образ на Node 24 LTS), **Express**, **esbuild / tsx** | Модульный REST API (`server/`), RBAC, защита от CSRF и перебора, раздача статики |
| **База данных** | **SQLite (`better-sqlite3`)** в режиме **WAL** | Встраиваемая реляционная СУБД (`./data/calendar_db.sqlite`) с `FOREIGN KEY ... ON DELETE CASCADE` и регистронезависимыми уникальными индексами |
| **Почтовый модуль** | **Nodemailer (SMTP)** | Отправка одноразовых 6-значных кодов восстановления пароля (RU/EN шаблоны, таймауты соединений) |
| **Инфраструктура** | **Docker (non-root `node`)**, **Docker Compose**, **Nginx + Certbot** | Многоэтапный production-образ без dev-зависимостей, healthcheck, обратный прокси и автоматический HTTPS |

### Модель данных (SQLite)
В базе данных включены внешние ключи (`PRAGMA foreign_keys = ON`) и используются 6 связанных таблиц с индексами:
- `users` — учетные записи пользователей (`id`, `username`, `email`, `password_hash`, `created_at`), уникальность `LOWER(username)` и `LOWER(email)`.
- `classrooms` — учебные группы (`id`, `name`, `description`, `owner_id`, `invite_code`, `is_closed`, `max_members`, `created_at`, `updated_at`).
- `members` — связь пользователей с группами и их роль (`owner`, `admin`, `member`), уникальность пары `(user_id, classroom_id)`, каскадное удаление при удалении класса или пользователя.
- `events` — календарные события класса (`title`, `description`, `starts_at`, `ends_at`, `creator_id`), индексация по `(classroom_id, starts_at)`.
- `sessions` — серверные сессии авторизации с поддержкой мгновенного отзыва (`revoked_at`) и периодической фоновой очисткой истекших записей.
- `reset_codes` — одноразовые коды сброса пароля (`code_hash`, `attempts`, `expires_at`, `used_at`).

## Ролевая модель доступа (RBAC)

Права пользователя определяются отдельно внутри каждого класса:

| Действие в классе | Владелец (`owner`) | Администратор (`admin`) | Участник (`member`) |
| :--- | :---: | :---: | :---: |
| Просмотр календаря, деталей событий и списка участников | Да | Да | Да |
| Создание, редактирование и удаление событий | Да | Да | Нет |
| Добавление обычных участников по логину | Да | Да | Нет |
| Исключение обычных участников (`member`) | Да | Да | Нет |
| Назначение и снятие администраторов (`admin`) | Да | Нет | Нет |
| Изменение настроек класса, закрытие входа, лимит участников | Да | Нет | Нет |
| Удаление класса | Да | Нет | Нет |
| Самостоятельный выход из класса | Нет (только удаление класса) | Да | Да |

## Быстрая установка на сервер (одной командой)

### Что требуется
- Чистый сервер **Ubuntu 20.04 / 22.04 / 24.04** или **Debian 11 / 12** с доступом в интернет.
- Минимум **512–1024 МБ ОЗУ** (установщик предложит 2 ГБ SWAP, если памяти меньше 2 ГБ).
- Доступ `root` (или пользователь с `sudo`).
- Для HTTPS: домен, **A-запись которого уже указывает на IP сервера**, и открытые в панели хостинга порты **80** и **443**.
- Для доступа по IP без домена: открытый порт приложения (по умолчанию **3000**).

### Установка
```bash
bash <(curl -Ls https://raw.githubusercontent.com/wisoqu/Interactive-calendar/main/install.sh)
```

Установщик задаёт вопросы в диалоговом режиме и сам делает всю настройку:

1. **Проверяет ОЗУ сервера**: если памяти меньше 2 ГБ и нет подкачки, предлагает автоматически создать `SWAP` на 2 ГБ для стабильной сборки на бюджетном VPS.
2. **Устанавливает зависимости**: `git`, `curl`, `Docker` и плагин `Docker Compose` (с официального сайта Docker), повторяя `apt-get` при временной блокировке пакетного менеджера.
3. **Скачивает проект** в `/opt/interactive-calendar` (или в указанную вами директорию) и создаёт каталог `./data` для постоянного хранения базы SQLite.
4. **Настраивает отправку писем (SMTP)**: запрашивает адрес и пароль приложения вашей почты (шаг можно пропустить нажатием `Enter`), корректно экранируя спецсимволы в `.env`.
5. **Собирает и запускает Docker-контейнер** от непривилегированного пользователя `node`, ждёт ответа `/api/health/db` до 90 секунд и при ошибке сразу показывает логи контейнера.
6. **Настраивает домен и HTTPS на порту 443** *(по желанию)*: проверяет DNS, устанавливает `Nginx` + `Certbot`, задаёт email для Let's Encrypt, переводит публикацию порта приложения на `BIND_HOST=127.0.0.1` (чтобы порт `3000` не торчал в интернет в обход HTTPS), прописывает проксирование, выпускает сертификат (с повтором при DNS-задержке) и проверяет цепочку `Nginx → приложение` через `https://<домен>/api/health`.
   Если домена нет, приложение сразу доступно по `http://<IP-сервера>:3000`.

### Неинтерактивный режим (автоматизация)
Все ответы можно передать флагами — удобно для CI, Ansible или повторной установки:
```bash
bash install.sh --yes --no-swap \
  --dir /opt/interactive-calendar \
  --domain calendar.school42.ru --email admin@school42.ru \
  --smtp-host smtp.yandex.ru --smtp-port 465 \
  --smtp-user calendar@school42.ru --smtp-pass 'app-password'
```
Полный список параметров: `bash install.sh --help` (есть `--dir`, `--domain`, `--email`, `--port`, `--ref`, `--no-ssl`, `--no-swap`, `--reconfigure-env`, `--smtp-*`).

### Повторный запуск и обновление
Повторный запуск установщика обновляет код (`git pull`) и пересобирает контейнер. Существующий `.env` **не перезаписывается** без `--reconfigure-env`, а настройки HTTPS (`BIND_HOST=127.0.0.1`, `TRUST_PROXY=1`) сохраняются:
```bash
bash /opt/interactive-calendar/install.sh --yes
```
Чтобы заново настроить почту: `bash install.sh --reconfigure-env` (или отредактируйте `.env` и выполните `docker compose up -d`).

### Где что лежит и как обслуживать
| Что | Где |
| :--- | :--- |
| Код проекта | `/opt/interactive-calendar` (меняется флагом `--dir`) |
| База данных SQLite | `/opt/interactive-calendar/data/calendar_db.sqlite` (WAL-файлы рядом) |
| Настройки окружения | `/opt/interactive-calendar/.env` (права `600`) |
| Журнал установки | `/var/log/interactive-calendar-install.log` |
| Логи контейнера | `cd /opt/interactive-calendar && docker compose logs -f` |

Согласованная резервная копия (скрипт сам остановит контейнер на пару секунд):
```bash
cd /opt/interactive-calendar
bash backup.sh                 # архив ~/calendar-backup-YYYY-MM-DD_HHMMSS.tgz, права 600
bash backup.sh /opt/interactive-calendar /root/my-backup.tgz   # свой путь
```
Восстановление: распакуйте архив в каталог проекта (`tar xzf ... -C /opt/interactive-calendar`) и выполните `docker compose up -d`.

## Как правильно настроить почту (SMTP) для сброса пароля

Чтобы приложение отправляло реальные письма с 6-значным кодом восстановления пароля, почтовые сервисы требуют использовать специальный **Пароль приложения** (ваш обычный пароль от почты для входа в браузере не подойдет из-за защиты аккаунтов).

### Вариант 1. Google Почта (Gmail)
1. Откройте [Настройки аккаунта Google -> Безопасность](https://myaccount.google.com/security).
2. Включите **Двухэтапную аутентификацию** (2-Step Verification).
3. В поиске по настройкам аккаунта введите **«Пароли приложений»** (*App passwords*) и создайте новый пароль (получится 16 символов).
4. Укажите при установке или в файле `.env`:
   ```env
   SMTP_HOST="smtp.gmail.com"
   SMTP_PORT=587
   SMTP_USER="ваш_адрес@gmail.com"
   SMTP_PASS="16_символьный_пароль_приложения"
   SMTP_FROM="Школьный календарь <ваш_адрес@gmail.com>"
   SMTP_SECURE=false
   ```

### Вариант 2. Яндекс Почта
1. Откройте [Яндекс ID -> Безопасность -> Пароли приложений](https://id.yandex.ru/security/app-passwords) и включите пароли приложений.
2. Создайте пароль для типа **«Почта»**.
3. В разделе настроек Яндекс Почты «Почтовые программы» убедитесь, что разрешен доступ к почтовому ящику с помощью почтовых клиентов.
4. Укажите при установке или в файле `.env`:
   ```env
   SMTP_HOST="smtp.yandex.ru"
   SMTP_PORT=465
   SMTP_USER="ваш_логин@yandex.ru"
   SMTP_PASS="пароль_приложения_яндекса"
   SMTP_FROM="Школьный календарь <ваш_логин@yandex.ru>"
   SMTP_SECURE=true
   ```

### Вариант 3. Почта Mail.ru
1. Перейдите в [Настройки Mail.ru -> Безопасность -> Пароли для внешних приложений](https://account.mail.ru/user/2-step-auth/passwords/) и создайте новый пароль.
2. Укажите при установке или в файле `.env`:
   ```env
   SMTP_HOST="smtp.mail.ru"
   SMTP_PORT=465
   SMTP_USER="ваш_ящик@mail.ru"
   SMTP_PASS="пароль_внешнего_приложения"
   SMTP_FROM="Школьный календарь <ваш_ящик@mail.ru>"
   SMTP_SECURE=true
   ```

> **Как изменить или включить почту уже после установки?**  
> Отредактируйте файл `/opt/interactive-calendar/.env` и пересоздайте контейнер одной командой:
> ```bash
> cd /opt/interactive-calendar
> nano .env
> docker compose up -d
> ```

## Ручная настройка HTTPS (Nginx + порт 443)

Если во время работы `install.sh` вы пропустили ввод домена и хотите подключить HTTPS позже вручную:

1. Направьте `A`-запись вашего домена на IP-адрес сервера и установите пакеты:
   ```bash
   sudo apt-get update
   sudo apt-get install -y nginx certbot python3-certbot-nginx
   ```
2. В файле `/opt/interactive-calendar/.env` установите `BIND_HOST=127.0.0.1` и `TRUST_PROXY=1`, затем перезапустите контейнер (`docker compose up -d`), чтобы закрыть прямой доступ к порту `3000` извне и разрешить приложению доверять заголовку `X-Forwarded-Proto` от Nginx (от него зависят `Secure`-cookie и HSTS).
3. Создайте файл `/etc/nginx/sites-available/interactive-calendar`:
   ```nginx
   server {
       listen 80;
       listen [::]:80;
       server_name calendar.example.ru; # укажите ваш домен

       location / {
           proxy_pass http://127.0.0.1:3000;
           proxy_http_version 1.1;
           proxy_set_header Upgrade $http_upgrade;
           proxy_set_header Connection 'upgrade';
           proxy_set_header Host $host;
           proxy_set_header X-Real-IP $remote_addr;
           proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
           proxy_set_header X-Forwarded-Proto $scheme;
       }
   }
   ```
4. Активируйте конфигурацию и выпустите сертификат Let's Encrypt (Certbot сам переведет сайт на порт `443` и включит автопродление):
   ```bash
   sudo ln -sf /etc/nginx/sites-available/interactive-calendar /etc/nginx/sites-enabled/interactive-calendar
   sudo nginx -t && sudo systemctl enable --now nginx && sudo systemctl reload-or-restart nginx
   sudo certbot --nginx -d calendar.example.ru
   ```

## Диагностика типовых проблем

| Симптом | Что проверить |
| :--- | :--- |
| `https://домен` не открывается | A-запись домена → IP сервера; порты 80/443 открыты в панели хостинга и в `ufw`/`firewalld`; `sudo nginx -t`; `sudo systemctl status nginx` |
| Certbot не выпускает сертификат | DNS ещё не обновился (повторите `sudo certbot --nginx -d домен`), порт 80 занят другим сервером, домен закрыт прокси-сервисом без поддержки HTTP-01 |
| `429 RATE_LIMITED` | Слишком много попыток для этого аккаунта/email (или общий анти-спам с одного IP). Подождите 15 минут или увеличьте `RATE_LIMIT_*_MAX` в `.env` и выполните `docker compose up -d` |
| Письма с кодом не приходят | В `.env` заполнены `SMTP_HOST/USER/PASS`, используется «пароль приложения», а не обычный пароль; проверьте `docker compose logs` на `[SMTP ERROR]` |
| Контейнер не стартует | `cd /opt/interactive-calendar && docker compose logs --tail=200`; проверьте свободное место `df -h` и права на `./data` |
| Забыт пароль, а почта не настроена | Восстановление по email недоступно. Настройте SMTP или создайте нового пользователя; прямого сброса без почты нет |
| Нужно сменить домен | Запустите `bash install.sh --domain новый.домен` — установщик обновит конфиг Nginx и выпустит новый сертификат |

Проверка работоспособности в любой момент:
```bash
curl -fsS https://ваш-домен/api/health
curl -fsS https://ваш-домен/api/health/db
```

## Локальный запуск для разработки и проверки

Требуется установленный **Node.js 22+** (Node 20 снят с поддержки в апреле 2026).

```bash
# 1. Клонирование репозитория и установка пакетов
git clone https://github.com/wisoqu/Interactive-calendar.git
cd Interactive-calendar
npm install

# 2. Создание файла окружения (по желанию заполните SMTP_*)
cp .env.example .env

# 3. Запуск в режиме разработки (доступно на http://localhost:3000)
npm run dev

# 4. Проверка строгой типизации TypeScript
npm run lint

# 5. Автоматический прогон всех тестов (безопасность, CSRF, RBAC, лимиты, OTP, SQLite, календарь, прокси)
npm test

# 6. Офлайн-проверка установщика (заглушки Docker/Nginx/Certbot, без сети и root)
npm run test:install

# 7. Полная проверка: типы + тесты + установщик + production-сборка
npm run check

# 8. Сборка производственной версии и запуск
npm run build
npm start
```
